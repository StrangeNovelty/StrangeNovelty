# Timeline and cross-reference domain

A Timeline is a Workspace chronology that may optionally belong to one Work. Multiple Timelines can represent primary story time, history, a Character, a faction, publication order, prophecy, or an alternate chronology without assuming one universal calendar.

A Timeline Event combines an author-controlled decimal sort value with a readable date or story-time label. Exact and approximate Events may use one sort position; ranges use start and end positions; relative and unknown Events may omit numeric positions. Labels preserve fictional calendar language while decimal keys provide stable ordering.

Chronology remains distinct from reader order. Reader order is derived from typed Chapter and Scene links and their structural positions. Connection roles distinguish an occurrence from a later reference, recollection, foreshadowing, or Reveal. Explicit Event relationships record before, after, simultaneous, overlap, causation, retelling, flashback, prophecy, and alternate versions without attempting temporal-logic solving.

Typed connections link Events to supported story, Character, worldbuilding, continuity, knowledge, ability, relationship, and Draw records. Appearance indexes and Cross-Reference queries derive counts and co-occurrence from those existing links. The system deliberately avoids a universal graph and free-form query language: supported relations remain explicit, Workspace-scoped, understandable, and independently validated.

Synthetic example: an Event sorted at `120.5` may display as “Third Bell, Floodnight,” be depicted in Chapter 8, and first revealed to the reader in Chapter 14. Those are three related but distinct facts.
