# Break-Glass Runbook

Break glass is exceptional, attributable, time-bounded, least-privileged access when documented interfaces cannot safely recover service. It is not a permanent account, shared password, routine shell, or authorization substitute.

Before access, record the bounded reason, approving owner/operator, intended scope, duration, release, backup state, and rollback plan. Use a temporary externally issued credential and the narrowest role. Take and verify a backup before destructive intervention.

Prefer read-only inspection. Direct production writes require a reviewed exact plan, maintenance mode, stopped workers, transaction boundaries, validation queries, and evidence. Never edit immutable Revisions or provenance casually, disable constraints globally, or expose private content in notes.

Afterward, revoke access, rotate any exposed credential, run integrity/readiness/recovery checks, record bounded outcomes, review Security Events and operational evidence, and conduct a post-action review. There is no universal break-glass password or hidden shell path.
